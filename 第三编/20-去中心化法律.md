# XX　去中心化法律

> “一旦我们用无尽的线圈环绕地球，穿越沙漠、穿越大洋，去中心化便不仅成为可能，而且成为必然。”
> ——凯文·凯利（Kevin Kelly）

我们终于来到本书的核心：**去中心化法律**。这一旅程从探索各种法源开始，始于完全去中心化的自然法，再到由自然法派生、包含各种去中心化要素的国际法。然而，我们发现：现代的立法观念预设中心化当局为法律的唯一创制者。因此，需要大量工作，才能把法律体系恢复为基于平等权利与义务的体系。还有什么比从地基向上建造它更好的方式？本章首先定义去中心化法律（DeLaw）。接着，它从比特币改进提案（Bitcoin Improvement Proposal）与当前 DAO 技术中汲取灵感，提出创制去中心化法律的观念。然后，它考察发布与接受去中心化法律的三种可能方法。最后，它提议以**法律维基**（Legal Wiki）作为发布与维护去中心化法律的理想技术。这一体系将使用基于规则的算法来管理修订，并确保法律保持简单、可理解。本章以探讨去中心化法律如何通过被引入其他法律层次而在社会中承担更显著角色作结。

## § 20.1. 定义

在通向去中心化法律的旅程上，我们进入未经探索的地带。在继续实践应用之前，我们必须确立一个清晰定义。既然尚无定义存在，就必须创制一个。让我们首先考察两个组成部分：“法律”与“去中心化”。

### “法律”的定义

首先，让我们沿用导论中所引《韦氏词典》（The Merriam-Webster Dictionary）的宽泛定义。按该定义，法律是

> “一个共同体有约束力的习俗或实践：由控制性权威规定或正式承认为有约束力或加以执行的行为或行动规则。”[^947]

关键之点在于：法律可以被承认，也可以被执行。法律并不需要执行才能成为法律。

### 法源

既有了方向，我们便可以收窄范围。我们得知法律有四种主要渊源：自然法、实证（政府）法、国际法，以及私法。我们也得知：在这些渊源之中，唯有私法使私人法律体系的创制成为可能。其结果是，私人当事方可以在共识管辖中以一套独特的定制规则组织自己。由于这一体系缺乏自上而下的执行，它只有在参与者明示承认为有约束力时才成为法律。去中心化法律是一种自愿的私法。

### “去中心化”的定义

“去中心化”一词虽然流行，却很少被定义。《剑桥词典》（The Cambridge Dictionary）给出如下定义：

> “把一个组织或政府的控制从一个单一地点移到若干较小地点。”[^948]

按这一定义，去中心化关乎“控制”的分布。而且，它同时适用于政府与私人组织。

《韦氏词典》将去中心化定义为：

> “职能与权力的分散或分布；特指，政府：把权力从中央当局委托给地区与地方当局。”[^949]

如果假定控制与权力是同义的，这一定义看起来与第一个相似。但它们是同义的吗？

### 权力与控制

第一个定义只讨论组织或政府之控制的分布，而非其权力。例如，如果欧盟重组，并把更多决策控制从欧盟委员会委托给议会，这并不改变欧盟的总体权力——只改变这一权力被行使的方式。第二个定义讨论的是权力而非控制的分布。但当涉及法律时，其权力可以被分布吗？法律的一般观念是：它高于社会中的每一个人——如托马斯·潘恩（Thomas Paine）所言，“法律即国王”。[^950] 如果法律的权力是绝对的，中心问题便变成：谁来指引这些权力。对我们的定义而言，我们应当关注的是“对立法权力的控制”。

### 实践中的去中心化

比特币网络的去中心化，超出组织或政府对控制的委托。相反，它创造一个由独立行动者“蜂群”治理、朝向单一目标合作的体系。许多网络随之而来，具有各种形式的去中心化。这些事业提供超越抽象理论的实践教训。布特林（Buterin）观察到存在三种去中心化：[^951]

- 架构性
- 政治性
- 逻辑性

**架构性去中心化**

架构性（去）中心化——一个体系由多少台物理计算机构成？在任一时刻，它可以容忍其中多少台计算机发生故障？在其最初十五年里，比特币提供了充足例子，说明为何去中心化体系不能依赖单一故障点。最著名的例子是前文讨论过的 Mt. Gox。必须指出的是，经历这些磨难时，比特币区块链本身按预期运作。因此，该体系证明：去中心化为其参与者带来巨大的安全与可用性益处。幸运的是，发布法律并不等同于提供货币服务。没有需要保全的不可变交易，没有需要防止的双重支付问题，没有需要考虑的监管问题，没有需要抵御的剧烈价格波动。法律可以是一份静态文件。去中心化法律基础设施的主要功能将是记录规则与协议。这一观念既不需要新型区块链，也不需要大规模技术创新。去中心化法律的开发可以在任何地方完成：上传到私人服务器上的开源协议、社交媒体群组，或既有论坛。要整合更高级的功能，例如智能合约块与共识管辖，才需要区块链。然而在此情形中，可以使用既有区块链（例如以太坊）。

**政治性去中心化**

政治性（去）中心化——最终控制构成该体系的计算机的，是多少个人或组织？

即便是去中心化的区块链，例如比特币，最终也会成为纷争与政治的温床。在挖矿与交易平台上大量投资的行动者，有动机试图影响项目方向。幸运的是，工作量证明与权益证明等共识技术，对个人行动产生内置限制。这些限制由代码执行。其结果是，政治对充分去中心化的网络应只有有限影响。

政治的限制在某些“第二层”项目上可能有所不同。[^952] 我们得知，任何希望合作或组织的群体都可以形成共识管辖。此类群体将发明性地经历人类一切组织中都能找到的同样政治争吵。然而，可能有成千上万个群体在几十条真正去中心化的区块链上运作。而且，这些体系是自愿的。其结果是，任何人都可以自由离开、加入，或建造具有更透明立法形式的体系。个别去中心化法律项目可能在政治上并非去中心化的——毕竟，整个要点就是通过政治过程创制法律——然而，总体体系是去中心化的。

只有一个潜在的政治瓶颈。私法在现实世界中的执行，取决于《纽约公约》或类似文书。个别民族国家可能撤回对这些文书的支持，尽管这是一个不太可能的情景。

**逻辑性**

逻辑性（去）中心化——该体系所呈现并维护的界面与数据结构，看起来更像一个单一的整体对象，还是一团无定形的蜂群？一个简单启发式可以帮助回答：如果你把该体系切成两半，包括提供者与用户，两半是否都会作为独立单元继续完全运作？

在此，矛盾变得明显。私法基于协议——参与者同意受某一套规则约束。协议背后的观念是：它在时间上约束人，尤其是在友好合作已经停止之后。一旦私法体系中发生争议，参与者不能追溯性地决定规则不再适用于他们。既已同意特定权利与义务，他们就必须尊重由此产生的后果。

超出这一限制之外，参与者——例如在共识管辖中——仍然可以“分叉出去”并建造自己的体系。他们更新后的协议适用于新的情形与未来的合作。共识管辖可以用无限方式被划分。最终，每一种变体都取决于构成该体系的个人的同意。没有比这更去中心化的了。

### 去中心化法律的定义

至此，我们概括了若干共同定义去中心化法律的标准。首先，我们在宽泛意义上接受法律。然后我们看到，只有私法允许实践上的去中心化。其结果是，去中心化法律必须被参与者所承认，因为不存在中心执行当局。我们进一步得知，要紧的不是法律的权力，而是对它的控制。最后，我们得知去中心化法律必须在去中心化基础设施上提供，并且不能通过单一政治结构来控制。

因此，去中心化法律的定义应如下：

> **一套自愿接受的私法体系之网络，其控制在政治上与技术上均被分布。**

## § 20.2. 创制

要开始创制去中心化法律，我们必须克服两道障碍。第一是发展一种使法律与规制得以产生的模型。第二，我们必须发展一种发布并接受这些法律的过程。比特币已被验证的开源软件开发实践，也为创制去中心化法律提供了一种模型。

比特币是一套完全去中心化的体系。其结果是，没有任何一个开发者对其机制负责。对协议的调整始于开发者提交一份**比特币改进提案**（Bitcoin Improvement Proposal，BIP）。[^953] 第一步是网络成员辩论这一 BIP 的必要性。任何人都可以参与这一公开讨论。与此同时，开发者测试并审视该 BIP，以确保其安全。发起者试图为其项目赢得支持，这可能涉及政治与说服。更广泛的共同体在这一过程中全程参与。在某一时点，该改进被推出。网络随后通过一种自愿、民主的过程决定接受或拒绝该改进：只有当足够多的用户接受并采纳它时，BIP 才生效。这一过程可以用如下 BIP 工作流来例示：[^954]

> **〔原书图示〕** 比特币改进提案工作流：提出草案 → 公开讨论与测试 → 争取支持 → 推出 → 网络自愿采纳或拒绝。

这一过程为比特币赢得了共同体的尊重与信任，使其得以无差错运作并持续改进达十五年。我们能否把这一过程作为社会其他方面的基础？

### Gitlaw

GitHub 是用于开源开发（包括 BIP）的主要工具。该网站使全球软件开发者能够在开源项目上协作。[^955] GitHub 运行在 Git 上——一种跟踪文件变更并在多个贡献者之间协调工作的版本控制系统。尽管 Git 主要在软件开发中管理源代码，它可以跟踪任何文件中的变更，包括文本文档。[^956]

Git 使多人能够在单一项目上合作，同时跟踪所有变更。它允许可以随后并入主项目的旁支项目。Git 进一步提供对项目历史与开发过程的完全可见性。此外，论坛使关于项目各方面的讨论成为可能。

鉴于其在软件共同体中的成功，立法者可以调整这一过程来创制法律。法律专家可以像对待开源软件项目那样协作立法。这一过程甚至可以使关于法律目标与内容的公共讨论成为可能。法律的某一特定条款或章节可以被分支出来并单独讨论。达成共识之后，贡献者可以把该条款合并回法律的主体。此类共识形式使未来的接受更为可能。当然，开发者可以设计一种专门用于法律开发的、类似 GitHub 的界面。

### 法律维基

公共维基是一种非常适于编纂与发布去中心化法律的技术。维基百科即公共维基的范例。维基百科运行在 MediaWiki 上——任何人都可以用来发布维基的开源软件。[^957]

维基很适合这一目的，既轻量又用户友好。公众知道如何使用维基，而维基擅长托管并结构化大段文本。此外，维基使易于超链接到相关条款、裁决与更高法律成为可能。这种可及性超越当前体系中宪法、裁决、法律与修正案的散乱集合。

这些维基可以使用星际文件系统（InterPlanetary File System，IPFS）等数据协议以去中心化方式存储。[^958] 投票机制将使共同体能够修订并批准这一立法。其结果是一套既被维护、也被以去中心化方式存储的法律。

## § 20.3. 发布

接下来，去中心化法律必须成为有约束力的。这通过发布及随后的接受来实现。理想情况下，接受先于发布。这样，遵循 BIP 过程模型，只有得到广泛支持的立法才会成为法律。以下是关于如何发布并接受去中心化法律的三种观念：静态发布、基于投票的体系，以及链上发布。

### 1）静态发布

法律由静态文件构成。与加密货币不同，这些文件不需要持续的交易验证与安全。当文件的创制服从开源开发过程、且接受是自愿的时，便可以保证充分程度的去中心化。因此，去中心化法律的简单静态发布或许就足够了。

受尊敬的专家、大学、科学出版物、非政府组织、贸易组织或政府机构可以发布并维护此类法律。共识管辖、像国际统一私法协会（UNIDROIT）这样的国际组织，以及行业特定组织，也很可能成为设定监管标准的候选者。以太坊或类似区块链可以为这些法律及其后续版本“打时间戳”以供核验。

本书先前引入了《去中心化自由权利法案》与《国家权利与义务宣言》，并提供了在区块链上查找它们的位置。那些就是法律静态发布的例子。

### 2）基于投票

投票过程可以决定法律的采纳。各种群体都可以参与投票，从行业参与者与社会群体，到共识管辖与地理共同体。DAO 中使用的技术代表着最合适的解决方案。由于开源软件的互操作性，既有 DAO 可以轻易增加这一功能。下一章引入 DAA——一种专门聚焦于立法与标准设定的创新型 DAO，把它的范围扩展到当前的金融／创业应用之外。

### 3）链上

可以推出一条特定的法律区块链（很可能是一种“第二层”解决方案）。这条区块链上的“交易”可以是公共维基上法律发布的哈希。或者，这一解决方案允许把整部法律存储在链上。[^959] 目前，任何人都可以对公共维基作出修订。另一方面，区块链可以在法律维基中保护发布与修订程序。例如，发布可能需要指定百分比的参与者批准，而修订可能需要五位立法者中的四位批准。多个项目可以竞争区块中的数据，从而为网络安全提供激励。或者，可以在既有链之上建造一个应用。

## § 20.4. 修订

尽管法律以最好的意图写成，它们也可能过时。技术与私人安排会变化。法律可能需要被调整以适应最新发展。有些条款可能需要改写，另一些可能变得多余。去中心化法律可以通过数学上受限制的修订过程来促成这一点。

### 基于规则的法律维基

设想法律维基上的一段法律，包含一千个词或六千个字符。立法内部硬编码的规则可以规定周期性变更何时以及如何发生。可以对可变更的字符或词数施加限制。以增加 10% 为例。在此例中，经修订的法律最多可以有 1,100 个词。此外，前文所述的发布过程可以治理修订的接受。

要修订一套法律体系，立法者通过改写条款并增加新条款来修改法律。字符限制要求清晰、简洁的写作。所有提案都必须落在体系边界之内。成功取决于清晰写作，并消除充斥法律文本的不必要语词与冗长句段。这一过程把法律文本其他令人沮丧的方面——例如法律行话与双重否定——减到最少。这一进路确保条款被仔细挑选，保持其本质含义，并以简单语词写成。这样的过程创制出有序、可及、简单、任何人都能理解的立法。它防止立法失控。这样，像比特币协议一样，去中心化法律可以逐渐演进以保持相关性。

变更法律可能导致法律不确定性或混乱。把修订限制在每年或每五年一次，可以处理这一问题。或者，该体系既可以保护核心领域不受修订，也可以只允许有限规模的附录。无论如何，去中心化法律中的版本控制使轻易发现任一特定时间适用哪些法律成为可能，并提供法律自那时以来如何变更的轨迹记录。

### 创制与维护去中心化法律的激励

在加密空间中，基于激励的体系已被证明在安全与可用性方面导向最佳结果。一份被广泛接受的立法可以像线上房地产那样运作，使创制者受益并推广他们。共识管辖可以通过提供最先进的法律与程序来竞争用户。用户可以为使用这些体系支付少量费用。作为交换，他们享有一套经过检验、既被良好维护又可执行的法律体系的保护。竞争将导致最佳体系的确立。它将导向专门化，正如开曼群岛已经发生的那样——它如今拥有对投资基金的精密规制。

需要法律框架的人可以浏览各种类别，类似于搜索 WordPress 主题，或在应用商店中寻找特定应用。市场可以发展出来，由受信任的供应商提供分类良好、星级评定的、即用的常见法律情景模板。共识管辖甚至可以拥有自己的仲裁庭，或与熟悉其体系的仲裁员建立联系。

## § 20.5. 去中心化法律桥接

商人法的一个著名例子发生在英格兰：中世纪集市上的商人发展出自己的法院与实践来规制贸易。随着英格兰法律体系变得更强、更统一，英格兰法官日益对商人之间的争议取得管辖权。然而，英格兰法官往往缺乏关于专门化商业的充分知识，以评估替代规则。据称，英格兰法官并不制定规则，而是寻求发现并选择性地执行既有的商人习俗。因此，法官所命令的是对商人实践的遵从，而非商人应当遵从何种实践。[^960] 按法理学中的一条古老原则，法官不能制定（普通）法，除非他们发现一种值得由国家执行的社会规范。他们必须从既有实践中提取法律，而不是发明某种全新之物。[^961]

现代经济创造许多专门化的商业共同体，各种区块链共同体——各自有其进路——也不例外。这些共同体的成员通过重复往来彼此发展关系。随着时间推移，他们确立规范以协调其往来。去中心化法律提供一种方式，把这一过程形式化，并建造与执行新的商人法。

加密行业可以使用在其生态系统中运作的定义与标准。这些领域包括：具有法律约束力的智能合约所需的特征；NFT 购买中的所有权；DAO 的治理标准（包括风险与责任划分）；被授权签署合同的数字／去中心化身份标准（包括作为增强匿名之表征的化名与哈希）；DeFi 交易中的支付形式化；电子商务与自由职业的条款与条件；发票、税务与会计标准；消费者保护标准；[^962] 围绕私人钱包财产权的定义；以及准据法与统一法文书的创制（带有使个别交易服从这些标准的选项标准）。

全书考察了在国家与国际两个层面形式化此类法律的可能性。不难想象一套原则如何成为国家立法的一部分。下一章所描述的工具甚至可以被直接纳入监管过程，例如由市政当局设立 DAA，让公民起草并制定他们自己的法律。或者，公民可以寻求这些法律的司法执行以确立先例。去中心化法律及其发展过程可以确立政府的第四个部门：自我治理。

随着时间推移，去中心化法律可以在国际、超国家或区域层面作为一套中立而平衡的习惯规则被普遍接受。它甚至可以被条约明确承认。或者，某些标准可以成为国家政策，或成为国际、超国家或区域层面机构的指引。

这一观念并不新鲜。行业组织常常为其产业起草监管标准。以证券市务实践小组（Securities Market Practice Group）为例，它成功地创制了全球商定、协调一致的市场实践，并与国际标准化组织（ISO）的标准相整合。[^963] 一群经纪／交易商、投资经理、托管银行与中央证券存管机构创制了标准，这些标准与监管者合作后成为 ISO 标准——把私人标准转化为国际法！加密行业可以追随这一范例。一旦可靠标准出现，政府将其纳入立法就是一种安全而受欢迎的选择。就执行而言，法官应当是独立的，并以其判断基于法律。对他们来说，法律如何被创制不应有区别。他们甚至可能更愿意基于得到广泛支持并被地方接受的去中心化法律作出裁决，而非基于来自日内瓦的、自上而下强制执行的国际标准。随着时间推移，仲裁庭在裁判争议时，可能会执行在共识管辖中发展出来的、经过验证的工具。

## § 20.6. 总结与阐释

去中心化法律（DeLaw）由一套自愿接受的私法体系之网络构成，其控制在政治上与技术上均被分布。

**关键要点：**

- 去中心化法律必须被参与者承认为有约束力；不存在中心执行当局。
- 比特币改进提案过程作为去中心化法律创制的模型，以公开讨论、测试与自愿民主采纳为特征。
- Git 的版本控制系统可以被调整以协作创制法律，使法律专家能够像对待开源软件项目那样处理立法。
- 法律维基体系是编纂与发布去中心化法律的理想选择，提供易于超链接、可及性与共同体参与。
- 提出三种发布与接受去中心化法律的方法：
  - 由受尊敬机构进行静态发布，并以区块链打时间戳。
  - 基于 DAO 的投票体系。
  - 专用法律区块链或第二层解决方案。
- 基于规则的修订过程通过修订与字符限制，使去中心化法律保持时新，同时防止复杂性。
- 去中心化法律的创制者通过提供专门化的法律体系与仲裁庭来竞争用户。
- 加密行业可以追随证券市务实践小组等范例，创制演变为正式法律的监管标准。
- 智能合约、NFT、DAO、去中心化身份、DeFi 交易以及其他与加密相关的法律框架，需要演进中的标准。
- 去中心化法律可以通过成为被纳入国家立法或国际条约的普遍接受标准，桥接到正式法律体系中。
- 法官可能更愿意基于得到广泛支持的去中心化法律、而非自上而下的（国际）法作出裁决。
